# 长篇连续性研究记录

本目录保存长篇小说连续性与分层记忆实验的规则、版本说明和结论。

## Prompt 版本

- `V0`：当前系统基线，不注入结构化交接和章节契约。
- `V1`：增加上一章结构化交接包。
- `V2`：增加 Planner 输出的章节连续性契约。
- `V3`：增加记忆权威边界和未知信息边界。
- `V4`：使用 Agent 专属召回并裁剪空的旧记忆字段。
- `V5`：使用定点重试策略，只有硬冲突或结构性缺陷才退回 Writer。
- `V6`：在 V5 基础上增加证据语言闸门和技术信息密度约束，不增加模型调用。
- `V7`：增加跨章物品状态账本与证据归属边界，不增加模型调用；完成独立十章复测。
- `V8`：将物品、能力、署名统一为证据对象，并压缩交接包中的重复来源和历史转移；两章部分复测因时间线边界暂停。
- `V9`：在 V8 基础上增加跨系统时间证据闸门；已完成十章正文生成，事件审计发现第 4 章最终发布缺少 `completed` 事件，不能把它当作完整无人工干预的十章指标样本。
- `V10`：在 V9 基础上压缩交接包、章节契约、角色卡和分层记忆的重复上下文；不增加模型调用，已完成独立十章复测。
- `V11`：在 V10 上增加历史/当前状态、倒计时周期和阶段性结论的结构化边界；保持 V10 上下文预算，不增加模型调用，已完成独立十章复测。
- `V12`：在 V11 上增加证据表面规则，区分读取路径、帧内来源字段、设备侧执行回执和实体影响，并明确关闭后的只读监测边界；已完成独立十章复测。
- `V13`：在 V12 上增加人物反应与叙事信息密度提示，不增加模型调用或记忆召回；已完成独立十章复测。
- `V14`：在 V13 上统一来源元数据字段与帧内来源字段，并增加行动收束规则；已完成独立十章复测。
- `V15`：在 V14 上增加最小证据清单与角色关系动作要求；第 1 章暴露 Planner 契约自身的数值和未知边界矛盾，未完成十章复测。
- `V16`：在 V15 上增加不增加模型调用的确定性契约卫生层，修正可计算数值矛盾并清理违反 unknown 地点边界的下游契约文本。
- `V17`：在 V16 上增加不增加模型调用的绝对时间与相对秒数一致性卫生，修正可计算的“X秒后/前”契约矛盾。
- `V18`：在 V17 上增加不增加模型调用的事件顺序卫生，修正同一事件中“同时”与明确先后关系冲突。
- `V19`：在 V18 上增加跨章倒计时/权限窗口状态卫生、收紧重复上下文预算，并强制长篇 Editor 记录完整七维质量评分。
- `V20`：以 V12 为低重试基线，恢复 V12 级上下文预算，只保留 V19 的跨章窗口/倒计时卫生；证据表面缺项和术语问题默认局部修复，不触发 Writer 重写。
- `V21`：在 V20 上增加数值时间线与断电缓存边界提示；实验显示仅靠提示词仍会产生多个倒计时基准。
- `V22`：将同一章节同一倒计时周期收敛为单一精确数值，后续只允许“继续递减”；新的精确值必须明确标注重置、校准或新周期。
- `V23`：在 V22 上增加时间锚点互斥规则；没有结构化映射时，精确时刻与不一致的精确“X分钟后/前”自动降级为“随后”。
- `V24`：在 V23 上增加继承状态账本；将上一章已成立的当前状态与本章真实变化分栏，并把已继承状态被重复写成“再次变化”的情况确定性降级为“仍保持”。
- `V25`：增加未登记实体与关闭只读窗口边界，防止模型凭空新增物品或把已关闭窗口写成重新开启。
- `V26`：将证据表面要求改为条件触发，避免没有真实证据账本时产生假契约。
- `V27`：叙事优先，移除 Planner/Writer 的无条件证据清单压力。
- `V28`：明确只读界面与实体动作归属，阻止界面确认直接导致设备或实体变化。
- `V29`：精简 Planner/Writer 生成提示和章节契约，只保留执行所需边界，减少说明书式重复表达。

每次实验 Job 通过 `params.experiment` 指定 `run_id`、`prompt_version` 和 `variant`。
完整模板、渲染后的 Prompt、模型响应和章节统计写入 `data/research_runs/<run_id>/`。

## 上线默认

上线默认固定为 Ariadne 研究中完成十章的 A28/V43。它保留权威事实边界，允许明确标注的假设推动可逆调查，并要求每章产生一个可观察叙事增量；V44-V66 继续作为研究版本，不通过数字版本的累积规则进入普通生产任务。生产默认通过 `NOVEL_CONTINUITY_PROMPT_VERSION=V43` 配置，研究 Job 仍可在 `params.experiment.prompt_version` 中显式选择历史版本。

## Provider

实验必须使用 `SystemSettings.active_provider_id` 指向名称为 `OpenAI` 的 provider。
运行记录保存 provider ID、模型、Base URL、Embedding 模型和是否配置 API Key，绝不保存 API Key。
如果 OpenAI provider 没有 `embedding_model`，记录会明确标记为 Chroma 本地 embedding。

## 质量门槛

七维质量平均分至少 8.5；连续性和伏笔兑现不得低于 8.5；其他维度不得低于 8.0。
平均每章内容重试不超过 1 次，至少 80% 章节零内容重试，硬性一致性错误为 0。

V9 的最后一条质量评估按十章记录平均为 `8.829`，剧情推进 `9.0`、人物塑造 `8.7`、世界观一致性 `9.0`、文笔 `8.0`、逻辑自洽 `8.8`、章节衔接 `9.3`、伏笔兑现 `9.0`，达到评分门槛。事件流累计观察到 `8` 次内容重试，十章中 `6` 章零内容重试，零重试率为 `60%`，未达到 `80%`。第 4 章的最终完成事件缺失，因此该版本只能作为质量和失败模式研究样本，不能宣布完整验收通过。

V9 的完整指标、章节表和原始事件缺口见 `versions/V9.md` 与 `results.md`。V9 结束后已修复暂停/恢复/人工发布路径的章节完成事件绑定，并通过完整测试；旧 V9 事件文件保持原样。下一步应使用同一 V9 提示词重新跑一组独立十章，确认事件链完整后再进入新的提示词版本。
