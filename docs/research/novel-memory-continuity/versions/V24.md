# V24 继承状态与本章变化边界

## 父版本与假设

- 父版本：V23
- 假设：V23 的时间锚点互斥规则已经消除了主要的相对时长算术冲突，但前三章仍各发生一次内容重试。
- 观察：V23 第 3 章的重试原因是上一章结尾已经确认 `TASK-0002 / TARGET：GATE-02`，本章 Planner 又把它写成“从短编号变成 GATE-02”；这是状态复述被错误建模为状态变化。
- 目标：把交接包中的“上一章已成立当前状态”和章节契约中的“本章新变化”显式分栏，降低状态复述类重试，不扩大记忆召回。

## 具体变化

- `ChapterHandoff` 新增 `inherited_state`，从上一章 accepted memory 构造 `inherited_current` 状态账本。
- 紧凑交接包优先保留 `inherited_state`，让 Planner、Writer、Editor、Validator、Extractor 使用同一份状态边界。
- 章节契约新增 `inherited_current_state` 规则：已继承状态只有在明确动作、撤回、转移、重置或新周期发生时才能改变。
- 对明确的“从上一章/之前的 X 变成已有编号 Y”文本做确定性下游清洗，原始 Planner 输出仍保留在实验快照中。
- V24 提示词要求五个 Agent 区分 inherited、current change、historical 三种范围。
- 不增加专门交接模型调用，不修改 V20-V23 原始实验数据。
