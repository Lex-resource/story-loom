# V17 确定性时间契约卫生层

## 假设

保留 V16 的契约卫生，在不增加模型调用的前提下，对同一结构化契约字段中的绝对时间、相对秒数和目标绝对时间进行确定性一致性校验。只有三个要素均可解析且差值方向明确时，才修正下游契约副本；Planner 原始输出和研究快照保持不变。

## 具体变化

- 支持 `HH:MM:SS` 绝对时间解析和合法性检查。
- 支持阿拉伯数字及常见中文数字的“X 秒后/前”。
- 当 `03:24:50 + 三十五秒` 的目标时间为 `03:25:00` 时，将下游副本修正为“十秒后”。
- 一致的相对时间保持原样，无法确定的表达不自动猜测。
- 修正发生在 Planner 输出到 Writer、Editor、Validator 的契约副本，不修改原始模型输出。

## 实际结果

仅完成第 1 章，随后 Validator 达到重写上限而暂停。Editor 第一次五维中间评分为 `9.2`，第一次内容修复后的五维评分为 `8.4`。最终章节事件记录：墙钟约 `450.314` 秒，内容重试 `3` 次，API/上游重试 `3` 次，JSON 修复 `0` 次，LLM 调用 `7` 次、尝试 `10` 次。

V17 没有再出现 V16 的“绝对时间加相对秒数”算术矛盾。暂停原因是同一事件的顺序表达冲突：开篇写“主潮位仪的数字同时跃升”，后文又写“主潮位仪先跳变，闸门才动”。这说明时间点卫生已经覆盖数值换算，但还没有约束事件因果顺序。

## 结论

V17 不作为完整十章成功样本。原始 Prompt、模型输出、重试指令和暂停事件均保留。下一版增加同一契约字段内显式事件排序词的确定性卫生，不增加模型调用。
