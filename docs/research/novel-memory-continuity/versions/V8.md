# V8 统一证据对象与紧凑交接

## 元数据

- 父版本：V7
- 修改假设：V7 的物品账本已减少物品状态回滚，但能力状态、署名归因和身份命题仍会在长上下文中被升级；完整交接包还重复携带来源和转移历史，增加 Writer 输入成本。
- 研究目标：在不增加模型调用的前提下，将物品、能力、署名/身份统一为可追溯证据命题，并压缩交接包中的重复上下文，降低证据边界内容重试和 Writer 输入 Token。

## 具体变更

1. `ChapterHandoff` 新增 `evidence_state_ledger`，每条记录保留证据类型、命题、状态、权威等级、来源章节和禁止升级规则。
2. 账本分类为 `item`、`capability`、`attribution`；只有 accepted atom 进入，candidate/generated 不进入当前事实账本。
3. 能力命题不能升级为永久能力、执行者或因果来源；署名/来源不能升级为本人留下、本人执行或身份核验成功。
4. V8 使用 `to_compact_prompt()`，保留上一章结尾、场景、角色、开放问题、当前状态和证据命题，移除来源列表与物品历史转移明细。
5. Planner、Writer、Editor、Validator、Extractor 都读取 V8 证据对象提示；不增加模型调用。

## 验证方式

先运行单元测试和单章 Prompt smoke test，确认 V8 账本不会引入 candidate，也不会丢失角色署名类 accepted atom；再使用独立项目、OpenAI provider、备用 provider 关闭的条件完成 10 章复测。实验目录保存完整模板、实际 Prompt、模型响应、章节指标和恢复事件。

## 预期验收

- 七维平均不低于 `8.5`。
- 连续性和伏笔兑现不低于 `8.5`。
- 平均内容重试不超过 `0.5/章`，至少 `70%` 章节零内容重试。
- 物品重复开封、状态回滚、无来源转移、未知身份/署名/能力/因果升级均为 `0`。
- Writer 的平均记忆上下文字符数相比 V7 降低至少 `20%`。
