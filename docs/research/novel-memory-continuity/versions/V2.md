# V2 交接包 + 共享章节契约

## 元数据

- 父版本：`V1`
- 修改假设：Planner 生成的章节契约由 Writer、Editor、Validator 共同读取，可把上一章状态、必须事件、状态变化、伏笔动作、禁止偏离和未知边界统一到同一份输入。
- Provider：`openai` / `gpt-5.6-luna`
- 正式实验：`v2-openai-tidal-20260810-schema-normalized`
- 项目：`64901094-ea3b-4faa-b8ce-bc4dd22e4bfc`
- 结果：第 2 章 Validator 达到重试上限后暂停。

## 失败证据与结论

第 2 章首轮 Validator 发现正文把录音直接归因于林砚本人；Writer 重写后又把“白色灯塔”直接定位为“白色信标区域”。两者都违反 Planner 契约的未知边界，但契约自身又在 `required_events` 中使用了“林砚的语音”，造成事实边界矛盾。

V2 的共享契约机制已经生效，但原样信任 Planner 的契约不够。V3 必须把 `published/user/frozen/accepted`、`candidate/generated` 和 `unknown` 的权威边界写入每个相关 Agent 的提示词，并在契约中明确“证据归属不等于事实身份”。
