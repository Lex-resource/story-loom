# V7 跨章物品状态账本与证据归属边界

## 元数据

- 父版本：V6
- 修改假设：V6 已能通过定点重写修复物品状态冲突，但交接包只带上一章的局部 accepted atom；跨章节物品的已完成转移可能被 Writer 重新执行，证据关联也可能被升级为个人归属或亲自执行。
- 研究目标：在不增加模型调用的前提下，让上一章交接包携带确定性的物品状态账本和证据边界，降低重复开封、状态回滚及证据归属越界造成的内容重试。

## 具体变更

1. `ChapterHandoff` 增加 `item_state_ledger`，读取主线中已接受的 `world_rule/item` atom，按 `memory_key` 汇总当前状态、来源章节和历史转移。
2. 账本只接受 `accepted` 状态，candidate/generated 仍只能作为线索，不会进入当前物品状态。
3. 交接包增加 `evidence_boundaries`，明确“关联、相似、指向”不等于人物归属、亲自执行、身份或因果确认。
4. 章节契约广播同一份账本和证据边界，五个 Agent 使用同一约束；V7 提示仅追加规则，不增加模型调用。
5. Validator 将重复开封、重复转移、状态回滚和证据归属升级列为硬连续性检查；Editor 优先局部限定修复。

## 完整提示词变更

V7 的运行时追加提示由 `agents/prompt_hints.py::v7_continuity_state_hint` 按 Agent 记录。V6 及之前的模板不覆盖，V7 实验目录会保存实际渲染 Prompt。

## 验证方式

使用与 V6 不共享正文或记忆的独立小说快照，保持 `OpenAI` provider、备用 provider 关闭，连续生成 10 章。逐章记录七维质量、内容/API/JSON 重试、LLM 调用/尝试、Token、记忆上下文字符数、墙钟和唯一 `chapter_finished` 事件。
