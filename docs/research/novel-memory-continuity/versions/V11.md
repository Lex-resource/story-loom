# V11 状态边界与阶段性结论

## 元数据

- 父版本：V10
- 修改假设：V10 已把记忆上下文压缩到可接受范围，但内容重试上升，失败集中在历史/当前权限、倒计时周期和阶段性结论的边界措辞。继续扩大召回会重新增加上下文成本，因此本轮只做确定性状态标注和 Agent 提示边界。
- 研究目标：在保持 V10 上下文预算和单一模型供应商不变的前提下，降低因状态边界歧义触发的内容重试，保持七维质量、连续性和伏笔兑现门槛。
- Provider：`OpenAI / gpt-5.6-luna`；备用 Provider：关闭；Embedding：`chroma_local`。

## 具体变更

1. `services/continuity_contract.py` 在 V11 下根据已有交接包和章节大纲，确定性生成 `state_boundary_rules` 与 `claim_boundary_rules`，不增加模型调用。
2. 权限、授权窗口、可见字段与撤回/关闭/锁定状态被标注为不同范围；历史授权范围不能覆盖当前权限状态。
3. 交接包的上一章结尾被标为继承状态，`state_changes`/`end_state` 被标为本章新状态，避免 Planner/Writer 把历史描述当作当前动作。
4. 检测到倒计时或帧周期时，契约要求明确承接同一周期或说明新周期的开始和旧周期的结束，禁止无说明重置。
5. 阶段性结论必须同时满足契约要求和未知边界：不能用模糊关联句替代必须落地的阶段结论，也不能把阶段结论扩展成完整因果或身份确认。
6. Planner、Writer、Editor、Validator、Extractor 各自接收 V11 角色化边界提示；上下文预算、召回数量和流水线调用次数保持 V10 不变。
7. `prompt_version_at_least` 支持 V11；V11 的完整模板、渲染 Prompt、原始输出和事件流写入独立 run 目录。

## 不变的约束

- 不新增交接包专用模型调用。
- 不改变四层记忆的数据源、权威等级和 PostgreSQL/Chroma 存储方式。
- `published/user/frozen/accepted` 才能直接作为事实；`candidate/generated` 只能作为待核对线索；`unknown` 禁止补全。
- 角色卡静态设定仍由角色系统维护，Extractor 不能覆盖核心设定。
- V5 定点重试、V7 证据账本、V8 统一证据对象、V9 时间证据闸门和 V10 上下文压缩继续生效。
- V10 历史项目和压缩包不修改；V11 使用独立项目、独立记忆和新的 `run_id`。

## 验证方式

先运行连续性契约和 Prompt 回归测试，再运行完整测试、`compileall` 和 `codegraph sync`。正式实验创建新的项目，只复制 V9 修复后复测的全书骨架，不复制正文、角色卡或四层记忆，连续生成 10 章。每章记录墙钟、各 Agent 耗时、内容/API/JSON 重试、Token、Prompt 字符数、分层记忆上下文分段、七维评分和原始事件。

## 预期验收

- 七维平均 `>= 8.5`；章节衔接和伏笔兑现 `>= 8.5`；其他维度 `>= 8.0`。
- 平均每章内容重试 `<= 1`，至少 `80%` 章节零内容重试。
- 硬性设定、角色状态和时间线冲突为 `0`；已到期伏笔兑现或明确推进率达到 `90%`。
- 最大记忆上下文不超过 V10 的 `26,991` 字符量级，不新增专用模型调用。

## 结果判断

V11 达到研究计划的质量门槛、平均内容重试门槛和零内容重试率门槛。前 9 章没有内容重试，第 7 章的倒计时问题由 Editor 局部修复，没有升级为 Writer 重写。第 10 章的 4 次内容重试集中在状态边界和证据表达：未校准观察顺序、阶段性证据链、关闭后的只读监测，以及“读取来源”和“帧内来源字段”的区别。

V11 的状态边界提示有效降低了前 9 章的重试，但没有彻底消除长篇收束段中的语言歧义。第 10 章最终正文虽通过 Validator 并发布，仍保留较容易被读者误解的表述：首次登记写成“来源显示为隔离监测窗口”，结尾写成“来源字段空白”。这应作为 V12 的确定性措辞修复点，而不是继续扩大召回。

运行审计发现本次恢复期间主机上同时运行了系统 Python 和项目 `.venv` 两组服务，导致第 10 章出现重复完成事件及并发沉淀调用。正式指标按合并完成事件计算，重复原始事件不计为额外章节；后续实验已清理为单一 `.venv` Worker。该运行审计问题不改变已发布正文，但 V12 必须在单 Worker 条件下重新验证。

完整提示词模板、实际渲染 Prompt、模型输出和事件流保留在本版本运行目录，未覆盖 V10 或其他历史版本。
