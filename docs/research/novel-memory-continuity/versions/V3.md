# V3 权威边界与 unknown 约束

## 元数据

- 父版本：`V2`
- 修改假设：共享章节契约不能原样信任 Planner 的事实表述；把来源权威、候选线索和未知边界分开后，Writer、Editor、Validator 应减少身份、时间线和物品状态冲突。
- Provider：`OpenAI` / `openai` / `gpt-5.6-luna`
- Embedding：未配置 OpenAI embedding，使用 Chroma 本地 embedding
- 备用 provider：关闭
- 代码状态：本地工作区 dirty，实验 manifest 保存 Git HEAD 和 diff 哈希

## 具体变更

1. 四层记忆召回继续直接提供 `accepted` 事实；`candidate/generated` 单独放入“待核对记忆线索”，禁止当作事实。
2. 章节契约加入 `authority_policy`、`authoritative_sources` 和 `uncertain_events`。
3. 对与 unknown 边界直接冲突的 Planner `key_events` 做确定性归一化：从 `required_events` 移入 `uncertain_events`，并从下游 outline 的 `key_events` 移除。
4. 所有下游 Agent 共享归一化后的契约和未知边界；unknown 只能产生观察、疑问、调查动作，不能产生身份、因果、生死或地点归属结论。
5. V3 提示词只增加权威等级和证据边界规则，保留 V2 的交接包与章节契约。

## V3.1 契约归一化修复

V3 首次运行暴露两个实现缺口：Planner 原始 JSON 已提供 required_events，但响应 schema 未声明该字段，导致它被丢弃；边界判定又把“观察到同一档案/图像”误判为“确认未知身份”。V3.1 保留显式 required_events，补充 uncertain_events schema，并要求 unknown 冲突同时满足断言词、关系类别和主体锚点；带有“未知/无法确认/证据不足”等不确定表述的事件继续作为调查动作保留。
