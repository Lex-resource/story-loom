# V10 上下文压缩与单一来源

## 元数据

- 父版本：V9
- 修改假设：V9 的连续性和伏笔指标已达到门槛，但 Writer/Editor/Validator 的上下文最大约 9.1 万字符，上一章原文、交接包、章节契约、角色卡和人物状态存在重复。重复信息会增加 token、延长墙钟，并让模型面对多个近似来源时难以判断边界。
- 研究目标：在不新增模型调用、不改变四层记忆数据源的前提下，降低实际渲染 Prompt 和记忆上下文大小，保持 V9 的质量、连续性和伏笔兑现水平。

## 具体变更

1. 增加确定性的 `services/context_compaction.py`，为 Planner、Writer、Editor、Validator、Extractor 设置记忆、交接、契约和角色上下文预算。
2. V10 将结构化交接包作为上一章结尾、物品状态账本、证据账本和未知边界的唯一 Prompt 来源；上一章原文只保留在确定性校验链路，不再与交接包一起发送给模型。
3. 章节契约只发送本章可执行的核心事件、状态变化、伏笔动作、结尾状态和禁止偏离项，不再重复携带交接包中的物品/证据账本。
4. 从发送给 Writer/Editor/Validator 的章节大纲中移除嵌套的 `continuity_contract`，契约仍通过专用字段发送，避免同一契约出现两次。
5. 角色卡、人物状态和四层记忆保留各自职责，但在 Prompt 中使用预算和去重规则，避免重复的静态设定与当前状态占用同一上下文空间。
6. 分层召回按 Agent 裁剪 Doctrine、Scene Block、Atom、到期伏笔和候选线索；V10 只注入有执行价值的摘要，完整来源仍保留在 PostgreSQL 和本地实验快照中。
7. 实验记录增加分段记忆上下文字符数，继续记录实际渲染 Prompt、原始模型输出、Token、API 重试、JSON 修复和内容重试。

## 不变的约束

- 不新增交接包专用模型调用。
- `published/user/frozen/accepted` 才能直接作为事实；`candidate/generated` 只作为待核对线索；`unknown` 禁止补全。
- 角色卡静态设定仍由角色系统维护，Extractor 只提交候选更新，不能覆盖核心设定。
- V9 的跨系统时间证据闸门、V8 证据对象账本和 V5 定点重试策略继续生效。
- 备用 Provider 关闭；本次实验使用 `OpenAI / gpt-5.6-luna`。OpenAI provider 未配置 embedding 模型时记录 `chroma_local`。

## 验证方式

使用 V9 修复后正式复测的同一全书骨架创建独立项目，不复制 V9 的正文、角色卡或四层记忆。使用新的 `run_id` 和 `prompt_version=V10` 连续生成 10 章。每章记录：墙钟耗时、Planner/Writer/Editor/Validator/Extractor 调用耗时、内容/API/JSON 重试、Token、实际 Prompt 字符数、分层记忆上下文分段字符数和七维质量评分。

## 预期验收

- 七维平均不低于 V9 修复后独立复测的 `8.699`，并达到研究门槛 `>= 8.5`。
- 章节衔接和伏笔兑现平均 `>= 8.5`，硬性设定、角色状态和时间线冲突为 `0`。
- 平均每章内容重试 `<= 1`，至少 `80%` 章节零内容重试。
- Writer/Editor/Validator 的最大记忆上下文相较 V9 明显下降，且不以新增模型调用换取压缩。

### 失败模式

1. 第 1 章：模型把尚未校准的广播、闸门和维护平台时间写成明确先后，并把数字序列升级为“有人或旧接口在利用误读”，还把旧接口和白色灯塔地下位置绑定。三类问题都属于 unknown/candidate 的语言升级。
2. 第 5 章：模型把历史授权范围写成当前仍有效的权限，连续三次定点重写才消除“原定权限”和“当前权限”的歧义。
3. 第 10 章：上一章已出现九秒计数器变化，本章又写成九秒重启但没有明确周期边界；恢复后又同时出现“已接入控制链”和“阶段性关联强度提高”两种不一致的证据表述。

### V10 结论

V10 将最大记忆上下文从 V9 修复后约 `91,336` 字符压缩到 `26,991` 字符，七维质量从 `8.699` 基本保持到 `8.700`，说明确定性压缩和单一来源规则没有损害质量，也没有增加模型调用。代价是内容重试从 V9 的 `2` 次上升到 `7` 次，零重试率从 `80%` 降到 `70%`。

因此 V10 不是最终版本：它证明“压缩上下文”有效，但尚未解决模型对历史/当前状态、周期边界和阶段性结论的措辞越界。下一版本 V11 只增加这些边界的结构化标注和契约归一化，不扩大召回、不增加模型调用，并继续沿用 V10 的上下文预算。
