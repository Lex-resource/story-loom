# V19 跨章状态与七维评估层

## 假设

V18 已证明同章事件顺序卫生有效，但第 10 章仍出现上一章已关闭读取窗口被重复关闭、倒计时数值回升的问题。V19 假设：把上一章动态状态作为确定性契约输入，在 Writer 之前清洗可机械判断的状态冲突，并减少重复交接包、章节契约、角色卡和记忆内容，可降低内容重试和后期上下文膨胀。

## 具体变化

- 对上一章已关闭/封存的读取或访问窗口，禁止下章重复关闭；下游契约改为确认只读封存状态。
- 对同一倒计时沿用上一章状态并单向递减；只有明确写出重置、校准或新周期时才允许回升。
- V19 使用更紧的 prompt-only 上下文预算；数据库、完整交接包和实验快照不删除。
- 长篇 Editor 在 V19 请求中强制输出 `chapter_continuity` 和 `foreshadowing_payoff`，质量事件必须能形成七维摘要。
- 不增加交接包专用模型调用，不修改 Planner 原始输出。

## 代码验证

- V19 状态卫生、上下文预算和既有 V16-V18 契约测试通过。
- 正式十章实验完成后补充逐章统计与结论。
