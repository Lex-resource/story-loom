# V6 证据语言与信息密度

## 元数据

- 父版本：V5
- 修改假设：V5 已能定位具体事实越界，但 Writer 仍可能在章节收束句把低置信度线索写成确认事实；技术字段连续堆叠也会降低逻辑自洽和文笔评分。
- 研究目标：在不增加模型调用的前提下，降低内容重试并提高逻辑自洽、文笔和人物塑造。

## 具体变更

1. Writer 增加证据语言闸门：确认句只用于权威事实，candidate/generated/unknown 使用观察、归因、疑问或调查表达。
2. Writer 增加技术信息密度约束：每段最多一组技术字段，连续技术段后必须通过动作、感官、对话或选择推进。
3. Validator 专门检查无限定确认句造成的证据等级升级；技术密度问题仅列 warning，不能单独触发内容重试。
4. Editor 在 V6 下优先局部修正低置信度确认句和重复技术字段，保持 V5 的低重试决策边界。
5. V6 不改变四层记忆、不增加交接包模型调用、不改变 API 重试统计。

## 验证方式

从与 V5 相同的小说初始快照创建独立项目，使用相同 OpenAI provider，先跑 10 章。记录每章质量、内容/API/JSON 重试、Token、上下文字符数和实际 Prompt。通过 V5 与 V6 的同口径结果比较是否降低内容重试，并观察逻辑自洽和文笔评分变化。
