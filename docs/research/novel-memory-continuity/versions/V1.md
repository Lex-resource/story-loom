# V1 上一章结构化交接包

## 元数据

- 父版本：`V0`
- 修改假设：把上一章的确定性结尾、场景、在场角色、状态变化、开放问题、伏笔和未知边界显式交给下一章，不增加模型调用。
- Provider：`openai` / `gpt-5.6-luna`
- 干净实验：`v1-openai-tidal-20260810-clean`
- 项目：`446e5164-fae4-4db8-8751-873446977f1d`
- 结果：第 1 章发布，第 2 章在 Validator 达到重试上限后暂停。

## 实现边界

交接包由 `services/chapter_continuity.py` 确定性生成，不调用 LLM。V1 的开关由 `continuity_handoff_hint()` 控制；V2 及以上才渲染章节契约，V3 及以上才渲染权威边界。

## 完整提示词

V1 的实际模板原样留档于：

`data/research_runs/v1-openai-tidal-20260810-clean/templates/V1/long_webnovel/`

每次实际渲染后的 system prompt、user prompt、模型输出和错误位于：

`data/research_runs/v1-openai-tidal-20260810-clean/prompts/chapter-XXXX/`

## 失败证据

第 2 章至少出现以下硬问题：

1. Writer 把只允许在机械隔离台内使用的一次临时副本拖入独立地图终端。
2. Writer 生成多个副本，超出已确认物品状态。
3. 重写时把记录时间早于死亡报告时间直接推断为父亲仍然存活，超出证据边界。

因此 V1 不能满足物品状态和未知信息边界要求，下一版必须把这些约束提升到 Planner 产出的共享章节契约中。
