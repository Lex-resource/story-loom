## A20 failure evidence

A20-r2 stopped at chapter 2 Validator. The chapter had no content, API, or
JSON retry, but Validator found repeated physical record artifacts that were
not present in `item_state_ledger`:

- `他掏出笔记本，迅速写下还能辨认的内容。`
- `林默的笔停在纸面上。`
- `他翻到笔记本新的一页……`

The problem was not that the ledger was unavailable. V35 hid the standalone
handoff and contract from Writer and retained only the narrative execution
brief, while the brief did not say how an abstract recording action must be
realized when no matching artifact exists.

## Controlled change

1. Add `recording_action_rules` to the deterministic chapter contract. The
   rule records whether physical recording artifacts are forbidden by an empty
   ledger or must match an existing ledger entry.
2. Add `recording_boundary` to the V36 Writer execution brief. The default
   choices are in-interface recording, spoken recapitulation, pure observation,
   or an already-present device explicitly listed in the item ledger.
3. Add one shared V36 role-specific prompt surface for Planner, Writer, Editor,
   Validator, and Extractor. It distinguishes an abstract recording action
   from a concrete notebook, paper, pen, page, original, copy, attachment, or
   folder.
4. Keep the V35 Writer surface, no-Polisher workflow, memory publication,
   review policy, and model/provider settings unchanged.

## Expected tradeoff

V36 may reduce incidental physical detail in scenes whose item ledger is
incomplete. That is acceptable for this experiment: a concrete prop should be
introduced by the canonical item ledger or by an explicit prior scene, not
inferred solely from the verb "record". The research comparison must check
whether the rule reduces hard item-state retries without producing sterile or
repetitive prose.
