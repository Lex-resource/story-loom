## Hypothesis

V64 reduced cross-chapter replay, but its fifth chapter showed a more fundamental failure: the prose moved into a new investigation stage while converting a drag mark into a confirmed carried object and an interface line into a confirmed real transfer. The Validator correctly detected the authority problem, but the pipeline treated both issues as chapter-level hard conflicts and ended with an error. V65 tests whether a shared observation/inference/unknown boundary plus a deterministic local-repair route can preserve the plot movement without paying for a Writer restart.

## Change

V65 keeps V64's stage boundary and adds role-specific evidence-boundary guidance to Planner, Writer, Editor, Validator, and Extractor. It also classifies source-boundary overclaims as Editor-local when they do not conflict with an accepted fact or cause a real state transition. The original Validator issue, replacement contract, and follow-up validation remain recorded.

No schema, memory layer, frontend surface, or extra model call is added.

## Runtime plan

Use a fresh project and memory namespace copied only from the fixed published chapter-1 seed. Use OpenAI / `gpt-5.6-luna`, disabled backup and hybrid recall, local Chroma embeddings, and generate chapters 2-10. Preserve A50/V64 artifacts unchanged and do not share generated prose or memory.

## Startup gate

The first Planner and Writer snapshots must contain the V65 marker. All five Agent prompt snapshots must contain the marker before the batch continues. The run must record provider/model, prompt version, code snapshot, actual prompts, memory context, retry classes, and final chapter events.
