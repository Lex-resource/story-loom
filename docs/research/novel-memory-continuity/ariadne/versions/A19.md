# A19 V34 Context Ownership and Current-State Projection

- Parent: `A18`
- Hypothesis: V33 fixes memory publication conflicts but does not change the
  amount of repeated continuity context shown to the Agents. Assigning one
  owner to each context block and exposing only the latest active projection
  should reduce stale/repeated instructions without weakening the stored audit
  trail or adding a model call.
- Prompt version: `V34`
- Variant: `ariadne-A19-v34-context-ownership-current-state-no-polisher`
- Extra default model calls: `0`
- Handoff/context source records: retained in PostgreSQL and local snapshots
- Hybrid recall: disabled
- Backup provider: disabled
- Provider: OpenAI / `gpt-5.6-luna`
- Embedding: `chroma_local`

## Controlled change

1. Add the V34 role-specific context-ownership surface. The handoff owns
   inherited state, the chapter contract owns current-chapter execution, the
   character card owns character facts, and layered memory only supplements
   uncovered accepted changes.
2. Render a V34 contract projection that omits inherited state and evidence
   ledgers already owned by the handoff.
3. Deduplicate agent-facing accepted atoms by `memory_key` and scene blocks by
   `(scope_type, scope_key)`, keeping only the latest chapter/version. Older
   records remain queryable and are not deleted or marked superseded by recall.

## Research questions

1. Does current-state projection reduce repeated or stale continuity material
   in Planner/Writer/Editor/Validator/Extractor prompts?
2. Does the smaller ownership surface improve natural prose and character
   portrayal while preserving continuity and foreshadowing payoff?
3. Does the change lower content retries and context/token cost without an
   additional model call?

## Acceptance gates

- Seven-dimensional average `>= 8.5`.
- Chapter continuity and foreshadowing payoff averages `>= 8.5`.
- Other dimensions average `>= 8.0`.
- Average content retries `<= 1` per chapter and at least 80% chapters have
  zero content retries.
- Hard setting, character-state, item-state, timeline, and action-ownership
  conflicts remain zero.
- No accepted/candidate/audit row is deleted by the projection.
- No additional handoff, summary, or quality-agent model call is introduced.
