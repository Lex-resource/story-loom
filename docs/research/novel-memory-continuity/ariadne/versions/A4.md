# A4 Deterministic Hybrid Recall

- Parent: `A3`
- Hypothesis: ranking a bounded PostgreSQL memory pool by the current chapter
  query, then adding advisory Chroma history, will improve relevant long-range
  recall without allowing vector results to override accepted facts or adding
  a dedicated model call.
- Ariadne commit: `480065e77a433d490aaa4671c0f65b44bc0919f3`
- Prompt version: `V12` (unchanged)
- Default embedding backend in the experiment: `chroma_local`
- Status: implementation complete; controlled ten-chapter smoke pending

## Implementation

- Expanded the existing PostgreSQL recall pool by a fixed factor of four.
- Added deterministic lexical ranking using normalized Latin tokens and CJK
  bigrams, with chapter/version recency as the stable tie-breaker.
- Built the recall query from the Agent query, current outline fields,
  previous-chapter ending, and handoff excerpt. This fixes Planner's former
  query of only `第 N 章`.
- Added role-specific advisory vector source budgets. Planner sees Scene Block
  projections; Writer, Editor, Validator, and Extractor may also see historical
  chapter extracts.
- Kept Chroma results explicitly `retrieved_advisory`; setting documents and
  future-chapter rows are excluded, and a Chroma failure falls back to the
  PostgreSQL result without changing publication state.
- Recorded a `memory_recall` event with candidate-pool size, accepted and
  candidate counts, vector hit count, and the hybrid flag.
- Added `ENABLE_NOVEL_HYBRID_RECALL`; set it on by default for this research
  branch and retain a one-switch rollback to the A3 path.

## Research boundary

A4 does not claim improved prose quality until it runs from the same chapter-1
snapshot as the A0/A2/A3 comparisons. The required next run is ten chapters
with V12, OpenAI as the sole provider, local Chroma embedding, all prompts and
`memory_recall` events archived, and no shared mutable memory with earlier
runs.
