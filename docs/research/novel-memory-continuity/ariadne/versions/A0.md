## Hypothesis

Ariadne's most transferable value is not its desktop workflow. It is the separation of Agent context assembly, narrative memory projections, provenance-aware facts, and atomic knowledge publication. These ideas can be added around the current PostgreSQL-backed four-layer memory without replacing it.

## Findings

1. Ariadne's `WritingContextAssembler` gives each Agent an explicit context contract. This is more precise than passing a large shared context object and is directly relevant to Planner/Writer/Editor/Validator/Extractor.
2. Ariadne separates story segments, story events, chapter summaries, stage summaries, and book direction. The current project has ChapterHandoff, SceneBlock, MemoryAtom, Evidence, Doctrine, and character cards, but no stable event/segment projection for long-range narrative traversal.
3. Ariadne preserves source spans and source versions on facts and summaries. The current project already stores source chapter, source reference, authority, confidence, validity range, and version; the gap is consistent section-level propagation into prompts and conflict review.
4. Ariadne has explicit fact proposals, two-step approval, and conflict records. The current project keeps candidates and protects canonical character data, but low-risk candidates are promoted after canonical updates. The Ariadne idea should be used only for hard authority conflicts so the low-retry baseline is not lost.
5. Ariadne's summary pipeline applies changes to a cloned state before publishing. The current post-processing path commits canonical data and aggregates Scene Block afterward, so the transaction boundary is a concrete improvement target.
6. Ariadne's hybrid retrieval combines vector and full-text ranks with deterministic RRF before optional reranking. The current project can evaluate this without adding a model call or making Chroma authoritative.

## Decision

Proceed with an isolated A1-A5 research series:

- A1: AgentContextBundle only.
- A2: A1 plus deterministic story event/segment/stage projections.
- A3: A2 plus hard-conflict queue and atomic canonical publication.
- A4: A3 plus deterministic full-text/vector hybrid recall.
- A5: gated quality agents only for explicitly high-risk chapters.

Do not import Ariadne source, add it as a dependency, or enable its extra Agents by default. Keep V12 as the production fallback until an independent experiment beats its quality and retry metrics.

## A0/V12 clean baseline run

Run: `data/research_runs/ariadne-a0-v12-baseline-10ch-20260815`

The run used a new PostgreSQL project with the same book outline and manually
published chapter-1 seed as the Ariadne exploratory sequence. Chapters 2-10
were generated continuously with narrative-index context disabled. The
provider was OpenAI / `gpt-5.6-luna`, with backup provider disabled and local
Chroma embeddings.

  `8.0`, logic `8.778`, continuity `9.111`, foreshadowing `8.889`
- Content retries: `4` total, `0.444/chapter`
- Zero-content-retry chapters: `5/9` (`55.56%`)
- API retries: `0`; JSON recoveries: `0`
- LLM calls: `67` total, `7.444/chapter`
- Wall-clock: `3,008.05s` total, `334.228s/chapter`
- Input/output tokens: `973,190` / `142,830`

The clean V12 baseline meets the overall quality average and the continuity
and foreshadowing thresholds, but fails the retry gate and the character
portrayal minimum. It is the control group for the fresh A2 run, not a
production selection.
