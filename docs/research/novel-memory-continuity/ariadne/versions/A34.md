## Problem From A33

A33/V47 produced a high-quality chapter 3 draft (`8.71/10`, zero content/API/JSON
retries), but post-processing paused it because the Extractor emitted generated
`merge` candidates for `B-17历史回执` and `白塔入口设备`. These candidates added
observable display and response details, not replacements of accepted hard facts.
The old allow-list did not include fields such as `visible_structure`, `layout`,
`adjacent_element`, `current_status`, or `response_scope`, so both candidates
were treated as hard conflicts.

## Hypothesis

The next limiting factor is the deterministic memory merge boundary rather than
the writing prompt. Allowing a bounded set of observation fields should let
normal generated state evolution publish without increasing retries, while the
existing hard-marker and authority checks continue to prevent silent fact
replacement.

## Controlled Change

V48 extends `_WORLD_RULE_OBSERVATION_FIELDS` with display, layout, response,
visibility, and state-observation fields. It does not alter the model prompts,
the four memory layers, database schema, context budgets, provider, or number
of Agent calls. `rule_type`, `confirmed`, `frozen`, and `locked` remain checked
by `_stable_field_conflict`; protected `published`, `user`, `frozen`, and
`system` authorities remain non-replaceable.

The V48 experiment uses the same fixed seed and runs chapters 2-10. It must
restart the Worker before generation and verify that the rendered snapshots
carry `prompt_version=V48` and retain the V47 narrative hint. The first
Extractor result must be inspected for accepted publication of the A33-shaped
world-rule observations, with no conflict queue item for those observations.

## A34-r2 Result

The first A34 attempt was excluded before quality measurement because the Job
started at chapter 1 and rewrote the fixed seed. Its project and raw events are
retained separately.

The clean r2 run used project `25bfd0d5-0af8-43e1-a5d3-116737478f27` and the
same chapter-1 seed. The startup gate passed: chapter 1 remained `published`,
chapter 2 started normally, and Planner/Writer/Editor/Validator snapshots used
`prompt_version=V48` with OpenAI and no backup provider.

Chapter 2 reached quality `8.71/10` with `7` LLM calls, `0` API retries, and
`0` JSON recoveries, but the run paused after `3` content retries. All three
retries were Validator/Writer reactions to evidence-language upgrades: the
draft treated an interface label as proof of a real historical record and then
inferred an actual sender/request and causal explanation. No Extractor memory
conflict was recorded, so the V48 deterministic merge fix itself worked for the
observed-memory case but did not meet the low-retry gate.

The next version is V49/A35: route this narrow observation-to-history/causality
class to deterministic Editor repair and make the Validator retry policy treat
it as locally repairable when no hard fact, timeline, location, item, or core
event changes.
