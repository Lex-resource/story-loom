## Implementation

- Added `NovelMemoryConflict` and migration `f3a4b5c6d7e8`.
- Added deterministic, idempotent hard-conflict queue writes.
- Added candidate review against the latest accepted atom in the same
  project/branch/storyline namespace.
- Conflicting `candidate/generated` atoms remain candidates and cannot replace
  accepted facts.
- Explicit `append_progress`, `resolve`, and `cancel` operations can supersede
  the prior accepted atom as a deliberate state transition.
- Evidence, atoms, character state, character vector outbox, scene blocks,
  narrative projections, chapter state, and project counters are prepared in
  one database transaction and committed once.
- Chroma remains downstream of the committed vector outbox; it is not part of
  the PostgreSQL transaction.
- Character-card stable data remains protected by the existing extractor
  authority boundary.
