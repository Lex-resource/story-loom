## Hypothesis

A49/V63 required a locally judgeable chapter objective, but the runtime still showed a serial exploration corridor: the next chapter could treat the previous chapter's completed exit, unchanged device state, waiting failure, or repeated unknown as a fresh action. V64 tests whether an explicit inherited-state boundary and a mandatory new-stage entry reduce cross-chapter replay without adding calls, fields, or memory layers.

## Change

V64 keeps V63 and adds role-specific guidance for Planner, Writer, Editor, Validator, and Extractor. The shared rule is: previous completed terminal state is an opening condition; it may be acknowledged once, but cannot be re-executed. The current chapter must enter a different stage through an existing `new_stage_delta`, `primary_action`, and `character_turn`. Narrative-only replay remains a warning and does not trigger Writer rewrite.
