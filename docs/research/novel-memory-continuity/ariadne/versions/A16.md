# A16 V31 Evidence-Ordered Continuity Execution

- Parent: `A15`
- Hypothesis: A15 bounded the generation handoff, but the Writer still turned
  an observed synchronization into a causal or calibrated temporal statement.
  The missing distinction is procedural: inherited observations, allowed
  actions, unknown relationships, and forbidden conclusions are present in the
  data but not presented as an ordered execution checklist. V31 makes that
  order explicit and asks Editor to repair locally fixable observation wording
  before Validator can request a Writer rewrite.

## Controlled change

A16 keeps A15's V30 compact handoff, V29 narrative-first prompt, shared
chapter contract, character cards, layered-memory publication, deterministic
hard validation, and no extra Polisher. V31 changes only prompt guidance:

1. Planner must keep `continuity_from_previous` as inherited state, put only
   observable actions in `required_events`, keep unresolved relations in
   `uncertain_events`, and repeat the boundary in `forbidden_deviations`.
2. Writer follows the sequence `inherit observable state -> choose/act -> show
   consequence`. For uncalibrated systems it may describe co-occurrence or
   uncertainty, but may not turn it into actual ordering, causality, source,
   identity, or control.
3. Editor treats unsupported words such as “导致/随后/先后/证明/因此” as
   local continuity-language defects when the underlying scene is valid. It
   rewrites the smallest sentence or clause and preserves the event, character
   action, and unknown boundary.
4. Validator keeps hard blocking for a remaining unsupported claim. Extractor
   records only the observation and its uncertainty.

No new summary, critic, polisher, or handoff model call is introduced.

## Research questions

1. Does the explicit execution order reduce unknown-boundary and uncalibrated
   temporal content retries compared with A15?
2. Does Editor local repair move these cases from Writer retries to accepted
   revisions without lowering continuity or foreshadowing scores?
3. Does the unchanged V30 context budget preserve prompt cost and latency?
