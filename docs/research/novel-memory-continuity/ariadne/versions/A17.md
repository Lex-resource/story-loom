# A17 V32 Compact Prompt Surface

- Parent: `A16`
- Hypothesis: V31 protects unknown relationships, but the accumulated prompt
  history still makes the Writer treat a chapter contract as a compliance
  checklist. Replacing the old hint blocks with one role-specific execution
  surface should preserve hard continuity while improving natural prose and
  reducing content retries.
- Prompt version: `V32`
- Variant: `ariadne-A17-v32-compact-prompt-surface-no-polisher`
- Extra default model calls: `0`
- Handoff/context budgets: unchanged from V30/V31
- Hybrid recall: disabled
- Backup provider: disabled

## Controlled change

V32 changes prompt assembly only:

1. Planner receives one short planning boundary and a compact contract-output
   requirement. It still distinguishes inherited state, current actions, and
   unknown relationships.
2. Writer receives one narrative-first rule surface. It still follows
   `inherited observable state -> character action/choice -> visible result`,
   but does not receive the historical V6-V31 rulebook.
3. Editor receives only the local-repair and hard-rewrite threshold relevant to
   its decision.
4. Validator receives only the authority, evidence, hard-conflict, and warning
   boundary relevant to validation.
5. Extractor receives only the publication boundary relevant to state
   extraction.

The older prompt branches remain unchanged for V31 and earlier runs. V32 does
not change memory recall, the four-layer publication transaction, schemas,
database tables, or the number of model calls.

## Research questions

1. Does a smaller prompt surface improve writing quality and character
   portrayal without lowering continuity or foreshadowing payoff?
2. Does it reduce checklist-like repetition and content retries?
3. Does it reduce per-agent input tokens and wall-clock time at the same
   context budget?

## Run protocol

Run ten chapters from the same clean chapter-1 snapshot as A16. Do not reuse
A16/A15 later chapters or memory. Record each chapter's seven scores,
content/API/JSON retry counts, LLM calls and attempts, token counts, wall-clock
time, memory context breakdown, prompt snapshots, raw responses, provider
snapshot, and hard conflict count.

The first clean run is valid only if all five relevant Agent snapshots contain
`V32 精简连续性提示面` or the corresponding `V32 章节契约输出要求`, and do
not contain the old V31 generation block. A run with stale worker code is an
infrastructure failure and must be retained but excluded from comparison.

## Acceptance gates

- Seven-dimensional average `>= 8.5`.
- Chapter continuity and foreshadowing payoff averages `>= 8.5`.
- Other dimensions average `>= 8.0`.
- Average content retries `<= 1` per chapter and at least 80% chapters have
  zero content retries.
- Hard setting, character-state, item-state, timeline, and action-ownership
  conflicts are zero.
- No additional model call is introduced.
