# 实验结果记录

## 研究口径

- Provider、模型、Base URL、embedding backend 和备用 provider 在每个 run manifest 中记录；API Key 只记录 `has_api_key`。
- `content_retry`、API 重试和 JSON 修复分开统计。
- 章节质量以 Editor 的七维评分为准；没有完整七维评分的历史结果不强行补分。

## 当前结论

V0 暴露了基线的调用重试与连续性问题。V1 证明“只给上一章结尾”不足以约束物品状态和证据推断，不能把交接包单独视为解决方案。V2 将让 Planner 生成的章节契约由 Writer、Editor、Validator 共同读取，重点验证硬事实、物品状态、禁止偏离和未知边界是否减少重试。

## V2 正式复测

V2 使用交接包和共享章节契约完成第 1、2 章后暂停。第 1 章平均质量 `8.71`，连续性 `10`，伏笔 `9`，内容重试 `0`；第 2 章平均质量 `8.57`，连续性 `9`，伏笔 `9`，但内容重试 `3`，最终因 Validator 重试上限暂停。

第 2 章的契约内部同时出现了“林砚的语音”和“不得确认声音就是林砚本人”，Writer 先后两次越过未知边界。该结果表明章节契约必须在生成后经过权威边界归一化，不能只把 Planner 输出原样广播给后续 Agent。完整记录见 `versions/V2.md`。
